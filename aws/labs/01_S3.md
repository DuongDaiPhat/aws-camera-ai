# Lab 01 — Upload ảnh vào S3 private và đọc bằng signed URL

## Mục tiêu và điều kiện

Sau lab 00, bạn tạo một bucket lab riêng, upload một ảnh không nhạy cảm và hiểu: bucket private vẫn có thể cung cấp link có thời hạn. Chưa cần model hoặc code NestJS.

## Thực hành

1. Console → **S3 → Create bucket**, Region Singapore. Chọn tên duy nhất toàn cục, ví dụ prefix `camerai-lab-media-` kèm hậu tố ngẫu nhiên. Giữ **Block all public access**, Object Ownership mặc định và encryption mặc định. Chưa bật versioning cho bài cơ bản để dễ dọn.
2. Upload một ảnh JPEG/PNG không nhạy cảm vào key **`lab/sample.jpg`**. Đây chỉ là bài S3; ảnh có khuôn mặt được dùng riêng ở lab 03 với sự đồng ý của người trong ảnh.
3. Trong cùng PowerShell đã cấu hình ở lab 00, nhập tên bucket thực tế và kiểm tra object:

   ```powershell
   $labBucket = Read-Host 'Ten bucket lab vua tao'
   aws s3api head-object --bucket $labBucket --key lab/sample.jpg --profile camerai-lab --region ap-southeast-1
   ```

4. Tạo link đọc có hạn 5 phút:

   ```powershell
   aws s3 presign "s3://$labBucket/lab/sample.jpg" --expires-in 300 --profile camerai-lab --region ap-southeast-1
   ```

   Mở link được trả về trong browser. Không commit link hoặc đưa nguyên query string vào ảnh báo cáo: link là quyền đọc tạm thời.

5. Trong Console copy **Object URL** không có chữ ký; mở ở cửa sổ riêng tư, không dùng link presign ở bước 4. Với bucket mới chưa có public policy, truy cập anonymous phải bị từ chối. Giữ block public access, không đổi bucket thành public để chữa lỗi.
6. Bucket → Management → Lifecycle rules: tạo rule cho prefix `lab/`, expire current objects sau 7 ngày; nếu UI hỏi thì xác nhận phạm vi rule. Kiểm tra rule Enabled. **Không đợi/xác nhận xóa bằng cách chạy lab vài phút:** expiration là bất đồng bộ; bài này kiểm tra cấu hình, không chứng minh đã qua 7 ngày.

## Kết quả cần thấy

| Thử nghiệm                          | Kết quả                                        |
| ----------------------------------- | ---------------------------------------------- |
| `head-object` bằng profile có quyền | Có metadata object                             |
| Presigned URL còn hạn               | Xem/tải được ảnh                               |
| Anonymous Object URL                | Không đọc được                                 |
| Lifecycle rule                      | Đúng prefix `lab/`, enabled, retention đã chọn |

## Gắn với CameraAI

Đọc `apps/orchestrator/src/storage/s3-storage.service.ts`: tìm `upload`, `download`, `getPresignedUrl`. Giải thích thao tác nào tương ứng từng bước vừa làm. Chưa đổi `.env` chung của nhóm; lab 04 sẽ nối bucket dev qua adapter hiện có.

## Lỗi thường gặp

- `NoSuchBucket`/`NoSuchKey`: kiểm tra đúng tên và chữ hoa/thường của key.
- `AccessDenied` từ CLI: quyền identity hoặc bucket policy, không phải lý do mở public bucket.
- Signed URL lỗi: kiểm tra Region, hạn URL/credentials và đồng hồ; tạo lại URL sau login nếu session hết hạn.
- Rule 7 ngày chưa xóa ngay: lifecycle không phải cron chạy đúng một giây xác định.

## Qua bài và dọn dẹp

- [ ] Một ảnh private; ký URL đọc được; anonymous bị chặn.
- [ ] Ghi rule lifecycle và giải thích ý nghĩa thời hạn signed URL khác retention object.
