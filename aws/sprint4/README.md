# Sprint 4 — Mỗi người tự hoàn thiện luồng E2E của mình

Cập nhật **17/11/2026** theo code tại `c3250bd` trên `feat/us-29-argus-dev-mode`. A và B dùng cùng hợp đồng G0, mỗi người có đầu vào tái hiện được và chạy E2E trên Dev của mình. C nhận cấu hình triển khai và quản lý AWS dùng chung/staging. A và B tự chạy lại tính năng trên staging sau deploy.

| Người | Luồng sở hữu                                                          | Điểm kết thúc có thể kiểm tra độc lập                                                                         |
| ----- | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| A     | [Cognito và toàn bộ thông báo AWS](02_NGUOI_A_DANG_NHAP_THONG_BAO.md) | Login và quyền bằng user test. Event hiện có → intent/claim → Sender → Results → trạng thái UI và email test. |
| B     | [Media, Face và Deadline](03_NGUOI_B_DU_LIEU_WORKFLOW.md)             | Camera → S3 → Face → DB/UI. Event có hạn → Step Functions → ack `NO_OP` hoặc `ESCALATED` với đúng một intent. |
| C     | [Cấu hình AWS, deploy và vận hành](04_NGUOI_C_HA_TANG_VAN_HANH.md)    | Cấp phạm vi Dev cần dùng, nhận cấu hình/ARN/alias từ A/B, áp dụng staging và kiểm release.                    |

A có thể dùng intent từ `EscalationEngineService` hiện có để phát triển SNS email. B dùng `EscalationRepository.createNotificationIntent()` đang có để tạo intent transactionally và nghiệm thu Deadline ngay trên nhánh B. A nối transport AWS tại đường tạo intent dùng chung. Khi cả hai PR đã ghép, chạy thêm **một ca timeout → intent → Sender → trạng thái và thông báo nhận được** để xác minh tích hợp. Một Results consumer tiếp tục định tuyến `face.result` và `notification.outcome`.

Môi trường Dev dùng tài khoản nhóm, Region `ap-southeast-1`, profile `camerai-lab` và quyền theo từng người. A/B dùng tài nguyên Dev đã cấp hoặc tài nguyên thử trong phạm vi đã được giao. Nếu dùng DB riêng, mỗi lượt dùng queue/worker trỏ cùng backend và DB. Với Lambda gọi ngược API trên laptop, dùng HTTPS tunnel cho callback hoặc dùng HTTPS của Dev App EC2. [Luồng Dev Cloud](../../docs/SPRINT4_DEV_CLOUD_LOCALHOST_TO_STAGING.md) · [Ma trận review/test](../../docs/test/SPRINT4_AWS_REVIEW_TEST_LOCAL_TO_STAGING.md)

`c3250bd` có Argus để đổi mode Dev. Trên nhánh thiếu Argus, chuyển mode bằng `.env` và `cloud_transport_mode` theo mục 5 của [tài liệu CI/CD](../../docs/CI_CD_STAGING_SOURCE_OF_TRUTH.md). Kiểm diff của PR để giữ thay đổi đúng phạm vi tính năng.

## Phối hợp với nhánh UI và API phân quyền

| Phần giao nhau                                                                          | Người giữ thay đổi và cách ghép                                                                                                                                                                                                                                                             |
| --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Login, callback, frontend session và màn hình chung                                     | Người làm UI giữ layout và ghép các entry point. A kiểm luồng Cognito đang có gồm `/auth/config`, code + PKCE, `/auth/callback`, refresh, logout. Mọi sửa lỗi auth riêng đưa vào PR nhỏ.                                                                                                    |
| `RolesGuard`, `ResourceAccessGuard`, `@Roles`, quyền household và policy người dùng     | Người làm API quyền giữ permission matrix và guard. A/B phát triển nghiệp vụ và dùng policy hiện hành. Khi đổi policy, review rõ các endpoint bị ảnh hưởng, nhất là xem event/media, known faces, xác nhận/đóng event và đọc outcome. Giữ test user thuộc hai household để kiểm quyền chéo. |
| Worker và internal API                                                                  | A giữ claim/outcome và Sender. B giữ Face và Deadline. `X-Internal-Token` dành cho worker. Mỗi handler vẫn kiểm event, owner, job/attempt và version trong DB. Quyền mới ở API người dùng cần giữ tương thích với các contract và điều kiện nghiệp vụ đó.                                   |
| `EventDetailModal`, dashboard thông báo, known faces                                    | A/B dùng các màn hình hiện có để nghiệm thu. Khi cần thêm trạng thái/field, tách phần dữ liệu hoặc component và giữ commit gắn UI chung nhỏ. Người làm UI ghép phần hiển thị vào layout cuối và chạy lại ca có quyền.                                                                       |
| `api/openapi.yaml`, generated contracts và migration                                    | Mỗi PR khai báo operation/DTO của mình. Khi ghép, giữ cả thay đổi đã review, sinh lại generated contracts từ OpenAPI hợp nhất và chạy contract tests. Phối hợp tên/thứ tự migration mới và test DB mới lẫn DB đã có dữ liệu.                                                                |
| `.github/workflows/cd.yml`, `deploy-environment.yml` và `services/aws-workers/build.py` | A/B bàn giao package và cấu hình worker riêng theo convention hiện có. Những đoạn workflow/build dùng chung được review trên diff đã ghép. Xác nhận CD cập nhật từng alias đúng với ZIP và giữ nguyên deploy Face. Các lượt Dev tự build để có thể thử trước khi ghép CD.                   |

Hai luồng AWS có thể triển khai song song với UI/API quyền. Trước khi chốt release kết hợp, chạy lại một lượt với quyền mới trên **cùng commit**. Kiểm login/refresh/logout, mỗi role cùng/khác household, URL ảnh, enroll/delete, ack/close và trạng thái thông báo. Chạy cả ca worker token sai và case duplicate để xác nhận đường nội bộ vẫn an toàn sau thay đổi quyền.

[Hợp đồng G0](00_HOP_DONG_G0.md) và [schema/fixtures](contracts/README.md) là căn cứ để hai nhánh tự chạy. Tài liệu tại `luu_tru_2026_11_05/` lưu lịch sử phân công cũ.
